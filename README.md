# Система управления задачами (Todo-лист)

Консольное приложение для ведения нескольких списков задач: создание задач,
смена статуса, приоритеты, дедлайны, теги, поиск и фильтрация. Данные
сохраняются в JSON-файл, поэтому после перезапуска ничего не теряется.

Проект написан на ООП: каждый класс отвечает за одну вещь, зависимости идут
только вниз по слоям.

## Слои

```
ConsoleUI        -> общается с пользователем (ввод/вывод)
   |
TaskManager      -> мозг приложения, вся бизнес-логика
   |
TaskList         -> контейнер задач (один список/проект)
   |
Task             -> одна конкретная задача

Storage          -> отдельная ветка: сохранение/загрузка (знает только dict)
```

Реализация: `Storage` (ABC) -> `JsonFileStorage` / `InMemoryStorage`.

## Файлы проекта

| Файл | Что внутри |
|---|---|
| `todo.py` | вся реализация в одном файле: исключения, `TaskStatus`/`Priority`, `Task`, `TaskList`, `Storage`/`JsonFileStorage`/`InMemoryStorage`, `TaskManager`, `ConsoleUI`, демонстрация и точка входа |
| `architecture.md` | техническое задание: классы, атрибуты, методы, инварианты |
| `manifest.md` | промт, по которому генерировался проект, и заметки о результате |

## Требования

- Python 3.9+ (использован `from __future__ import annotations`)

## Запуск

```bash
# демонстрация: прогон основных сценариев без ввода с клавиатуры
python todo.py

# интерактивный консольный режим
python todo.py --console
```

В интерактивном режиме данные пишутся в `data.json` (создаётся автоматически,
при сохранении рядом появляется `data.json.bak`).

## Команды консольного режима

`id` можно указывать по первым 4 символам (UUID).

| Команда | Назначение |
|---|---|
| `help` | справка по командам |
| `lists` | показать все списки |
| `use <id\|имя>` | выбрать активный список |
| `create-list <имя> [описание...]` | создать список |
| `rename-list <id\|имя> <новое имя>` | переименовать список |
| `delete-list <id\|имя>` | удалить список (с подтверждением) |
| `add [название задачи]` | добавить задачу (без аргумента — диалог) |
| `show` | задачи активного списка |
| `search <текст>` | поиск по всем спискам |
| `filter <статус\|-> <приоритет\|-> <тег\|->` | фильтр активного списка |
| `start` / `done` / `cancel` / `reopen <id>` | сменить статус задачи |
| `edit <id> поле=значение ...` | `title` / `description` / `priority` / `deadline` / `tags` |
| `delete <id>` | удалить задачу |
| `move <id> <список>` | перенести задачу в другой список |
| `overdue` | просроченные задачи |
| `stats` | статистика |
| `quit` / `exit` | выход |

Статусы: `new`, `in_progress`, `done`, `canceled`.
Приоритеты: `low`, `medium`, `high`.

## Бизнес-правила (инварианты)

1. `id` уникален и неизменяем; задачи сравниваются по `id`, не по названию.
2. `title` не пустой и не длиннее 120 символов.
3. Дедлайн нельзя поставить в прошлом.
4. Переходы статусов: `NEW -> IN_PROGRESS -> DONE`; из `DONE` только `reopen()`;
   `CANCELED` — из любого незавершённого.
5. Имена списков уникальны; последний список удалить нельзя.
6. Любая мутация данных заканчивается сохранением.
7. Удаление списка удаляет его задачи (UI спрашивает подтверждение).
8. Ошибки не роняют приложение: UI ловит `TodoError` и печатает понятный текст.
